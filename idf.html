01 · What IDF is

Execution got cheap. Judgment didn’t.

IDF governs the layer above execution: which outcome you pursue, who checks the work, who decides customers see it, and who confirms it worked. It is the operating framework behind The Judgment Layer, a free book for leaders.

02 · The Intent

Every piece of work starts with an outcome

An Intent is a team’s commitment to move a business outcome. It says what must become true for a customer and how you’ll know, and leaves out what to build.

Customer outcome

Reduce checkout abandonment at the payment step

What must become true. The team stays free to choose the implementation.

by Mechanism

by pre-filling saved payment details for returning customers

The product decision that scopes the cycle. Changing it means a new Direction review.

measured by Signal

abandonment below 12% (now 22%)

Declared before delivery, so nobody picks it after seeing the data.

If you can name the outcome but not the signal, you don’t have an intent yet.

Only the outcome owner closes an intent. Abandoned is a legitimate result.

Work with no customer outcome

Obligation

Must happen whatever customers see: a compliance mandate, a certificate rotation, a migration. Measure it with DORA.

Enabler

An intent can’t happen without it: a payments API, a data platform. It names the intents it serves at Direction and is confirmed when they are.

Neither

If nobody can name an intent it serves, call it an obligation, or admit it is work nobody needs yet.

Forcing this work into the intent template produces fiction. The enabler rule is reasoned, not yet measured.

03 · Cycle and Iteration

Intents hold cycles. Cycles hold iterations.

A Cycle is one delivery run with one release. An Iteration is one implementation pass inside it.

IntentReduce checkout abandonment
Cycle 1→ Live-ON
Iteration 1 · initial ✓
Cycle 2→ Live-ON
2a · initial ✗→2b · fitness-feedback ✓

Cycle

Runs from Direction to Exposure. No time-box: it closes when the release is authorized.

Iteration

The first is initial. Each rework is fitness-feedback, with the reviewer’s reason attached. After three reworks, the cycle goes back to Direction.

How the cycle’s output reaches customers

Toggle default

Deployed OFF. Exposure turns it ON for everyone.

Canary

Deployed OFF, then released to a subset. Exposure sets the audience and widens it as the signal builds.

Always-on

No switch: infrastructure, migrations, refactors. Exposure approves the deployment itself.

The pattern is agreed at Direction. The judgment is the same in all three.

Moving along

Teams often start spec-driven and move toward agentic as the tooling earns trust. IDF doesn’t prescribe a starting point.

On spec-driven

The tooling isn’t settled, and overhead grows at both ends of scope. Use it where wrong work is costly and scope is stable.

Agent teams

Agents running in parallel need tasks that are independent. The Iteration Record becomes the coordination surface.

10 · Is it working?

Six numbers that measure judgment

They move slower and flatter less. Your first honest quarter will look like a regression without being one.

SWITCH OFFVelocityStory pointsBurndownEstimation accuracyCapacity utilization

They measure bandwidth that agents absorbed. Finance uses velocity to plan headcount, so put a replacement in place first.

Intent completion rate

Intents confirmed versus abandoned. The primary number; the other five diagnose it.

The tell: ask to see the abandoned ones. Expect 60–80% if the team attempts hard things (an expectation, not a benchmark).

Pending-OFF age

How long finished work waits unreleased. Median and oldest.

The tell: ask for the oldest item by name.

Time from intent to customer

From outcome agreed to customers able to use it.

The tell: intents always dated the day work started.

First-pass rate per moment

Work clearing each moment without rework. Never aggregate the four.

The tell: a moment that never rejects anything is only recording.

Rework cause mix

Rework by root cause: intent, agent misreading or scope change.

The tell: everything filed as scope change.

Escape rate

Released items you had to withdraw. Read it with Pending-OFF age.

The tell: days between knowing about a problem and switching it off.

11 · Context debt

Context debt makes no noise

A stale entry throws no error. The agent reads it, believes it, and builds something coherent and wrong.

Memory pollution

Entries that were true once.

  • Abandoned decisions never removed
  • Dead-OFF features referenced as live
  • Entries that contradict each other

Skills and configuration

Practice the team no longer follows.

  • Superseded skills still active
  • Fitness corrections never encoded
  • Tools the Registry never granted

Compaction loss

Detail dropped inside one long session.

  • Mid-session decisions never written
  • Rejected approaches proposed again
  • Feedback drifted from by the end of a pass

If a decision has to survive, write it into the record. The conversation won’t keep it.

Context Reset audit checklist
System Memory · per entry
  • Still true in the current codebase?
  • Would an agent need it for a cycle today?
  • Contradicts another entry? Resolve it.
  • References a Dead-OFF switch? Remove it.
Skills Catalog · per skill
  • Invoked in the last N cycles?
  • Trigger conditions still match use?
  • Matches recent Builder output?
  • Recurring Fitness corrections harvested?
Connectors and binding
  • Only active skills referenced?
  • Every connector still in use?
  • Validated against the current workflow?
  • Anything on a deprecated protocol? Retire it on the vendor’s schedule.
Agent Registry · per entry
  • Named, current owner?
  • Every granted tool still needed?
  • Can it reach anything unlisted? Check the live configuration.
  • Irreversible actions behind human approval? Test one.
  • Does revocation work? Disable one agent and confirm it stops.

EU AI Act · as of August 2026

Article 50 transparency obligations have applied since 2 August 2026: tell people when they deal with an AI system and mark generated content in machine-readable form. Marking on systems already on the market has a grace period to 2 December 2026. The Digital Omnibus, in force since 27 July 2026, moved high-risk obligations to 2 December 2027 (Annex III) and 2 August 2028 (AI in regulated products).
